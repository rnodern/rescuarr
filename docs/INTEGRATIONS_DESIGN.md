# Rescuarr integration contracts

Sonarr and Radarr own wanted media, profiles, release selection, grabs, imports, and downloader mutations. Rescuarr reads each instance, decides whether intervention is justified, invokes an allowlisted operation, and independently verifies its effects. One Go process schedules the integration work and records checkpoints and outcomes in SQLite. The optional SABnzbd connection supplements evidence. Prowl is an outbound notification destination. The browser communicates only with Rescuarr.

### Connection and capability lifecycle

1. Allocate a permanent local UUID per configured upstream. Accept a user-entered HTTP or HTTPS base URL, including any reverse-proxy path prefix. Normalize the trailing slash and safely append relative endpoint segments. Reject userinfo, fragments and query strings in base URLs. Enforce outbound network policy for the configured destination. Ignore upstream URLs as action destinations. Keep the key in the secrets store and use `X-Api-Key` for Arr requests. Both pinned Arr schemas document this header. [Sonarr OpenAPI](https://github.com/Sonarr/Sonarr/blob/v4.0.20.3014/src/Sonarr.Api.V3/openapi.json) · [Radarr OpenAPI](https://github.com/Radarr/Radarr/blob/v6.4.4.10685/src/Radarr.Api.V3/openapi.json)
2. GET `/api/v3/system/status`. Validate a recognizable product and strict application-version shape. Retain normalized product, version, branch, package, OS family, reported URL base and process start time. Show mismatches in setup without silently rewriting the base URL. Check health and a one-record queue read using the explicit unknown-item flag. A UI login page, auth error, empty unexpected response or schema mismatch fails that probe.
3. Resolve an adapter capability manifest for product, app version, API generation and relevant client/configuration. Track each feature as `verified`, `read_only`, `unverified`, `temporarily_unavailable`, or `unsupported` with a reason and last check. Safe probes establish reachable/readable interfaces only. Write qualification comes from tagged source review, contract fixtures, and reproducible disposable upstream tests for the exact behavior in question. Read probes and OpenAPI expose interface availability. The side-effect contract depends on the source and disposable tests.
4. Keep broad compatibility through read-only shape checks. Missing and unknown fields degrade the features that require them. Development branches, forks, newly upgraded versions, and incompatible versions stay read-only until they match a qualified contract. On a version, base URL, credentials, client category, or preservation-relevant setting change, clear cached capabilities and pending write authorizations, then reconcile outstanding operations. A user can pause automation or enable a qualified capability. Configuration alone cannot mark a write path qualified.
5. Treat a changed server behind an existing address as a new identity epoch when the user confirms a rebind. Evidence of a database reset, restore, clone or conflicting entity identity suspends writes until that rebind or verification of continuity. System status supplies descriptive fields rather than a durable Arr database UUID. A routine restart refreshes mutable caches within the existing epoch. A rebind retains the local connection UUID and advances its epoch, archiving old mappings and proposals. Never apply old intents to the new epoch. Deduplicate duplicate configurations after probing and require explicit resolution of potential aliases before any write.
6. Keep Observe, Assist and Autonomous permissions per instance and operation. The Arr API key may carry wider powers, so the application enforces the operation allowlist at the integration boundary as well as in the workflow. Keep manual UI actions and scheduled actions behind the same adapter checks, schema validation and readback.

### Adapter boundary

Each Arr adapter supplies typed operations for status, paged queue, queue details, targeted history, target and profile reads, current library files, health, root capacity, remote path mappings, log samples, preview, candidate reprocess, exact import, queue reject, blocklist verification, exact search and command verification. Its request builders encode only supported endpoint paths, named parameters and explicit booleans. There is no browser-facing generic HTTP relay or arbitrary Arr command input.

Normalize data into independent types for observed state, evidence, desired content, command acknowledgements, and verified effects. Required identity and safety fields must validate before crossing into write planning. Raw enum strings may be retained for diagnostics. Unrecognized values enter an explicit unknown state. Optional sources fail independently. An outage in Prowl or SABnzbd may affect notification or evidence for a specific action while Arr observation continues.

### Identity and provenance

- The upstream key is local instance UUID plus typed local ID. Keep queue IDs, history IDs, Arr media IDs, file IDs and command IDs in separate domains. A queue row ID is an ephemeral write selector. The durable job key uses Arr instance UUID, protocol, resolved downloader identity and normalized `downloadId` where all components are known. Preserve the original token for upstream queries. Normalize a torrent hash only under a recognized hash format and adapter rule. Other tokens are opaque.
- Group all Sonarr rows for one download across episode IDs. Persist immutable observed membership and refresh before any job-wide action. Multiple Arr instances can see the same client job. Group across instances only when an owner-configured binding and exact verified client ID establish the shared client namespace. Shared membership gates physical actions even if one Arr has an otherwise clear failure. A downloader display name, path, title, external media ID or apparent season alone is insufficient to bind jobs.
- Bind queue rows to the Arr grab using matching `downloadId`, matching target IDs and protocol, and coherent grab time and client evidence. Download IDs can be missing, reused after reset, or appear with multiple historical grabs. Keep an attempt generation and require unambiguous lineage to authorize action. Keep conflicting provenance visible, including queue shows one movie while history identifies another.
- History's top-level type, media IDs, `downloadId`, date and title are separate from its flexible `data` map. Extract version-recognized source/indexer, release source, client, flags and size only when present. Exact labels are display evidence. Infer no provider identity from a domain inside an untrusted URL. Never fetch or render a recorded NZB URL, torrent URL, tracker, auth token, credentialed path, script output or other raw provider field. Keep path values only in their relevant namespace and use only scoped, server-observed paths for actions. The pinned controllers filter exact download ID and expose history event types through their schemas. [Sonarr history](https://github.com/Sonarr/Sonarr/blob/v4.0.20.3014/src/Sonarr.Api.V3/History/HistoryController.cs) · [Radarr history](https://github.com/Radarr/Radarr/blob/v6.4.4.10685/src/Radarr.Api.V3/History/HistoryController.cs)
- Quality intent comes from the live Arr target and profile. Capture profile ID and digest for decision evidence, plus whether a later profile change superseded the proposal. Preserve native quality group/revision and format IDs. Descriptions, display strings, historical release quality, and filename resolution never establish eligibility on their own. A matching native proposal is needed for import. Search continues to use Arr selection.

### Pagination and polling

Start with `page=1`, explicit `pageSize=100` for queue and `50` for targeted history, logs or blocklist, adjusted by measured latency. Request `sortKey=added` for queues and `sortKey=date` for history and blocklist, descending where relevant, with a supported key and direction per adapter. The queue controller enumerates supported sort keys and uses time-left by default. The log controller accepts `id` or `time` and can return `time` in the response after sorting by ID. Match expected paging structure without requiring that every echoed sort label equals the request literally. [Sonarr queue](https://github.com/Sonarr/Sonarr/blob/v4.0.20.3014/src/Sonarr.Api.V3/Queue/QueueController.cs) · [Radarr queue](https://github.com/Radarr/Radarr/blob/v6.4.4.10685/src/Radarr.Api.V3/Queue/QueueController.cs) · [Sonarr logs](https://github.com/Sonarr/Sonarr/blob/v4.0.20.3014/src/Sonarr.Api.V3/Logs/LogController.cs) · [Radarr logs](https://github.com/Radarr/Radarr/blob/v6.4.4.10685/src/Radarr.Api.V3/Logs/LogController.cs)

Treat paging totals as hints from a changing collection. Dedupe by typed record ID across pages, cap the cycle by response bytes, elapsed time and pages, and track duplicate windows, impossible totals or nonadvancing pages. Queue refresh can revisit a moving head and cross-check the target group. Historical reads use an overlap window and dedupe by event ID. Partial scans can add positive observations and never establish job absence or complete blast radius. A paused or rejected action retains the last evidence and its timestamp until fresh eligible reads arrive.

Use adaptive polling with jitter and coalescing. The default queue interval is 45 seconds with active cases and 120 seconds when quiet, with a targeted refresh following a useful event. A supported owner-configured webhook can mark an instance or target dirty after authentication and replay checks. Treat webhooks as wake-ups and fetch state independently. Fetch health and disk space every five minutes, with targeted refresh before relevant operations. Fetch roots and path mappings on setup, configuration changes, on-demand diagnosis and slow reconciliation. Pull log excerpts on incident formation or explicit inspection. Reduce duplicate fetches across cases via request coalescing and a short per-instance cache. Use per-instance and global limits, with a separate, prioritized write reconciliation lane.

## Ecosystem health, paths and capacity

Maintain independent measures for Rescuarr's own data directory, Arr library roots, and downloader incomplete and complete volumes. Each evidence record includes namespace, role, upstream instance, source endpoint, observed time, value, freshness and identity confidence. Show unknown when the source cannot measure a path. Never sum roots or mounts unless their underlying volume identity is independently established. Two apps can see the same NAS export under different paths. A mount point, container root, network share or thin provisioned quota can make an apparently positive total irrelevant to the actual write.

- Arr `/diskspace` describes disk/mount paths known to that Arr process, and may omit entries when free or total space is unavailable. `/rootfolder` describes Arr-configured roots and their reported accessibility/free space. Its list can collect unmapped folders, so keep it off the hot path. Find the longest known component-boundary root that contains the media path, using the upstream OS's path semantics. Preserve drive and UNC shares as separate namespaces. Fall back to unknown for ambiguous mappings, overlapping mount views or stale readings. [Sonarr disk-space service](https://github.com/Sonarr/Sonarr/blob/v4.0.20.3014/src/NzbDrone.Core/DiskSpace/DiskSpaceService.cs) · [Radarr disk-space service](https://github.com/Radarr/Radarr/blob/v6.4.4.10685/src/NzbDrone.Core/DiskSpace/DiskSpaceService.cs) · [Sonarr root controller](https://github.com/Sonarr/Sonarr/blob/v4.0.20.3014/src/Sonarr.Api.V3/RootFolders/RootFolderController.cs)
- Model downloader-native, Arr-visible, and optional Rescuarr inspection paths separately. `/remotepathmapping` gives Arr's configured downloader host, remote prefix and Arr-local prefix. Use it to explain likely mapping errors. Treat `outputPath` and the download-ID-driven preview as Arr-visible facts. Do not apply a second mapping to an already translated path. Never pass an operator-entered local path or a downloader-sourced path straight into an Arr preview or import operation. A local probe can augment diagnosis only within a read-only, owner-mapped scope.
- Estimate enough destination headroom for the bytes that may be copied, plus reserves and any bounded concurrent operation claims. Treat copy fallback as possible unless independently proven otherwise. Capacity is a point-in-time estimate. No amount of free space proves the service account can write or that a later network copy will succeed. Fresh low space or inaccessible root should gate affected automation. Unknown capacity keeps capacity-sensitive actions out of autonomous execution unless the recovery policy defines a separately justified, bounded alternative for that capability.
- Group related path, permissions, disk, authentication, indexer and client failures by instance and exact affected scope. A single storage incident may explain many import blocks. Correlate Arr health, structured queue messages, measured storage and relevant warning logs. Attach log snippets as supporting evidence with source, clock and confidence. Time proximity without a unique association remains contextual. Normalize known warning patterns with typed extractors and track unrecognized versions/localizations as unknown. A generic write error may be disk, permission or network failure and never justifies blocklisting.
- The Arr log endpoint can return empty paging data when its log database is disabled. Distinguish unsupported, empty, stale and unreachable where possible. Avoid automatic reads of `/log/file/{filename}`, raw traces or support dumps. Do not change Arr log levels. Keep Rescuarr's own decision and operational logs available independently of Arr's logging configuration. [Sonarr log controller](https://github.com/Sonarr/Sonarr/blob/v4.0.20.3014/src/Sonarr.Api.V3/Logs/LogController.cs) · [Radarr log controller](https://github.com/Radarr/Radarr/blob/v6.4.4.10685/src/Radarr.Api.V3/Logs/LogController.cs)

## Job-scoped import

### Candidate discovery and validation

1. Obtain the current exact download ID, tracked state, output-path evidence, target and complete relevant job membership. For both products, GET `/manualimport?downloadId=...&filterExistingFiles=false` in a bounded, decision-triggered probe. On the pinned releases, the core resolves that token through tracked downloads and takes the tracked output path. Sonarr takes a different media-library branch if `seriesId` is supplied. Keep that argument out of download-scoped Sonarr requests. Use the exact downloader token and leave folder selection to the upstream. Test the behavior of `filterExistingFiles` against existing-file, missing-file and candidate-limit fixtures. 3. `POST /manualimport` on the pinned contracts reprocesses an array of candidate mappings and returns reevaluated metadata/rejections. In the absence of that qualification, Observe uses the GET preview only. Restrict reprocessing to exact previously observed candidate paths and product-specific typed fields. Sonarr accepts series/season/episode selection. Radarr accepts a movie selection. Rescuarr can supply a uniquely evidenced target from the exact original grab for reevaluation, for example when Arr cannot parse the filename. It holds when quality, language, format, rejection or candidate identity remains unresolved. An accepted reevaluation is one input to plan eligibility. Require fresh independent checks before dispatch. ## Reject, blocklist and replace

### Arr queue operation

Use single-row `DELETE /queue/{id}` only after a fresh full job-scope read, exact correlation to grab history, proof of independent release failure and all policy, capacity, ownership and preservation gates. Send every flag explicitly. Ban the bulk queue endpoint and pending-release branch in automatic recovery. A Sonarr row may select a whole download, so all linked episodes and any shared ownership must be evaluated before selecting it. The upstream operation has no compare-and-swap token. Keep the preflight-to-send window short and stop on ambiguity or concurrent change.

| Purpose | `removeFromClient` | `blocklist` | `skipRedownload` | `changeCategory` | Design condition |
| --- | --- | --- | --- | --- | --- |
| Reject and preserve client data | false | true | true | false | Requires qualified behavior and positive verification that Arr recorded the rejection. Can stop tracking the old queue job. Only send for a proven rejected release whose preserved job does not conflict with the new intent. |
| Reject and remove proven unusable job | true | true | true | false | Only for a dedicated, exact USENET job, a tested Arr/SAB version pair, independent read-side terminal and ownership evidence, explicit policy and verifiable effect. Block on shared, partial or ambiguous membership and when source preservation is required. |
| Ignore already-satisfied queue entry | false | false | true | false | Optional, separately qualified workflow. The pinned controllers may create a persistent ignored-download record. Use only after exact target file verification and review of client retention implications. |
| Let upstream own replacement | Adapter-qualified | true | false | false | Compatibility behavior may be shown for a user acting in Arr. Rescuarr's orchestrated replacement uses `skipRedownload=true`. If upstream owns a search, observe its result and avoid a duplicate explicit command. |

At the pinned releases, removing from the client calls upstream `RemoveItem` with data deletion enabled, before `MarkAsFailed` attempts to emit the failed event. The latter depends on grabbed history. Missing history can leave a stopped/removed job without a blocklist event. Sonarr builds failure scope using the grabbed episodes for that download ID. Pending releases take their own implementation path, and the all-false removal branch can create an ignored record. These branches make queue absence and HTTP status weak evidence for the composite action. The History `POST /history/failed/{id}` path has different behavior and lacks a reliable skip-redownload contract for this use. Keep it out of the executor. ### Independent readback and scoped search

1. Snapshot relevant queue group, grab/history IDs, existing blocklist IDs, target files, current client disposition and any in-flight Arr command. Journal planned action and preflight evidence before network dispatch.
2. Reconcile separately. Record queue rows absent or still present, `downloadFailed` history tied to the original job, blocklist state for the exact title, target IDs, protocol, indexer and comparable quality data, and client/job disposition if observable. The blocklist resources do not expose a direct download ID. Require a consistent, unique join to fresh failure history and a matching blocklist row. A preexisting matching row can establish present state but does not attribute insertion to this operation. Hold on conflicting or insufficient readback. The failure event also carries a skip flag used by the Arr redownload service. Sonarr uses `POST /command` with `name=EpisodeSearch` and an explicitly bounded list of local `episodeIds`. The target episodes must be still wanted, monitored, aired under policy, unserved by an eligible import and scoped to this case. Radarr uses `name=MoviesSearch` and one local ID in `movieIds`. Recheck availability, monitoring, quality, cutoff and eligible existing downloads. The upstream API command is treated as manually triggered by the controllers. Radarr's handler explicitly permits manual searches to go beyond the normal monitored/available filter. Rescuarr therefore applies its own intent gate before calling it. Avoid the broader season command for automatic recovery. Whole-season and library searches have separate blast radii and can remain in the native UI. 4. Verify search acknowledgement, command outcome, then an independently observed new eligible grab and eventual import. Use scoped history and queue and distinct job identity. ## Optional SABnzbd observations

Core Arr compatibility covers supported download clients through Arr itself. SABnzbd is the only direct downloader adapter in this design. It is optional for ordinary Arr observation and low-risk supported actions. Client-specific destructive actions that need positive terminal and ownership evidence remain gated without a qualified source of that evidence.

| Purpose | SABnzbd request | Evidence and limits |
| --- | --- | --- |
| Reachability and version | GET `/api?mode=version&output=json` | SAB documents version as requiring no key. Treat this as a product/network probe. Verify the full API key separately with a minimal allowed diagnostic read. |
| Current status | GET `/api?mode=queue&output=json` using `nzo_ids` for a scoped job read | Preserve the exact `nzo_id`, queue state, category, progress and known labels from a bounded response. Active download, pause, propagation and repair/fetch states block final-failure assumptions. |
| Completion and diagnosis | GET `/api?mode=history&output=json` using `nzo_ids`, with bounded `start` and `limit` | Capture terminal versus ongoing post-processing state, normalized failure class, known stage names, category, size, timestamps and masked path evidence if necessary. Treat `loaded`, queued post-processing, repair, extraction, move or script stages as active where applicable. Keep snippets redacted and discard raw stage logs. |
| Disk summary | The small queue response, using available disk-space fields | Normalize units using a version-tested fixture for the incomplete/complete roles. Treat displayed human-readable units and unknown precision conservatively. Use readings to explain likely constraints only for the matching SAB instance/volume. |

Bind each optional SAB instance to an exact Arr download-client configuration during setup. Compare Arr `downloadId` to SAB `nzo_id` only after that binding and protocol validation. Pinned Arr SAB adapters populate the Arr item download ID from SAB's item ID. A global queue warning or missing history row cannot prove a particular job failed. History may be purged, archived, bounded by filters or changing concurrently. A completed download plus unpack failure is not sufficient evidence of missing or unusable media. Diagnose password, incomplete articles, post-processing and disk/permission conditions using tested patterns and independent case evidence. ## Transport, resilience and audit

- Reuse an HTTP client per upstream origin with bounded per-host connections and keepalive. Proposed initial budgets are 3 seconds to connect, 10 seconds for routine read or acknowledgement, and 30 seconds for a qualified targeted preview, with a strict per-response cap and separate command completion window. A healthy service may still time out on storage operations, so apply route-specific backoff and isolate the observer from slow paths. Limit JSON nesting, decompressed bytes, list entries, free-text lengths and retained body fields.
- Respect valid `Retry-After` with a configured ceiling. Retry safe reads with capped exponential backoff and jitter. On 401/403 enter a credential or access incident and slow probes. On 404 distinguish bad base path, unsupported capability, lost target, and an aged-out command using the originating request type. A 2xx HTML body, malformed payload, timeout or 5xx after dispatch leaves a write outcome uncertain. Treat an explicit contract-qualified rejection as effect-free only when that status is proven to occur before writes. A generic non-2xx response cannot safely infer that an upstream composite operation produced no effect.
- Durably store typed operation parameters or protected references, capability version, policy revision, observed identity, preflight record IDs, dispatch time, result and reconciliation evidence. Mark dispatching before making the call. A crash after dispatch but before acknowledgement is reconciled against external state on restart. The executor must reserve or deduplicate the exact operation while its outcome is unknown. Disable transport-layer request replay for effectful calls, including automatic behavior based on idempotent HTTP verbs. Arr sends no Rescuarr-owned idempotency token for these calls.
- Use validated TLS and trusted private CA configuration where applicable. Explicit local HTTP can be used by an owner-configured trusted network, with the UI showing that credentials transit without TLS. Do not follow redirects for credentialed adapter requests. Avoid inheriting environment proxies silently. Pin requests to configured origins, guard resolution according to local network policy, and prevent webhooks, upstream strings, credentials or user-supplied path values from changing destinations.
- Log operation kind, local instance and case IDs, HTTP status, latency, attempt and normalized reason. Strip API keys, cookies, authorization, credentialed URLs, file paths, arbitrary body strings, embedded XML error details, and untrusted links before writing logs, metrics, event streams or support exports. Use relative or masked paths where evidence display requires context, with administrator-controlled local inspection for sensitive context. Keep path material separate from support exports. Metrics use bounded labels, and command bodies and log excerpts require explicit field-level redaction.

## Prowl

Prowl receives selected user-enabled events such as action required, recovery summary, incident opened/resolved and automation paused. Feed a durable SQLite outbox in the same transaction that publishes a committed case or incident transition. One background worker makes one request per destination key and notification. This keeps recovery independent of Prowl availability and provides per-key invalidation, quota and delivery state. No provider key or account-registration flow is required for an operator-supplied key.

- Use HTTPS `POST https://api.prowlapp.com/publicapi/add` with UTF-8 form fields `apikey`, `application`, and at least one of `event` or `description`, plus approved `priority` and optional `url`. Validate lengths in UTF-8 bytes and truncate at rune boundaries inside documented limits. Prowl supports priorities from -2 to 2. Default summary/recovery to 0 and elevated incidents to 1 when enabled. Priority 2 requires a specific user setting because it can bypass device quiet hours. Use GET `/publicapi/verify` only when the key is entered/rotated and the operator requests validation. A separate explicit test notification checks delivery end-to-end. [Prowl API](https://www.prowlapp.com/api.php#add)
- Default to privacy-preserving summaries such as an incident count, cause class and scope label. Provide optional title inclusion per destination. Include a deep link only when the operator configured a suitable Rescuarr public/base URL. Construct it from the application route and opaque case/incident ID, with ordinary authentication at arrival. Reject userinfo, query credentials, embedded bearer tokens, service URLs, arbitrary upstream content and unapproved destinations. Respect local quiet hours, coalesce bursts by incident or case, and use one independently configurable digest.
- Parse bounded XML and verify both HTTP outcome and the documented `<success code="200">` or `<error code="...">` structure. A valid acceptance means Prowl accepted the notification. Device presentation remains external. Read the returned remaining/reset quota and schedule locally. The public API documents a standard IP quota of 1,000 calls per hour, so use an internal rate cap and incident dedupe well below the external ceiling. [Prowl limits and responses](https://www.prowlapp.com/api.php#limits)
- Use local uniqueness by destination, event category and semantic transition ID or digest window. Persist pending, sending, accepted, suppressed, delayed, failed and uncertain outcomes. Pause and surface invalid keys on 401, fail bad request data on 400, and defer rate-limited 406 or conventional 429 responses until a bounded reset interval. Retry documented, explicit transient failure with capped jitter. A disconnect after submission may have accepted the event. Prowl exposes no client idempotency token in this API. Hold uncertain alerts or apply a user-configured one-repeat limit for high-priority incidents where duplicate notifications are preferable to missing one. Recovery continues during the notification outage. [Prowl error codes and success payload](https://www.prowlapp.com/api.php#return)

## Qualification and release checks

All destructive and import-side-effect tests use isolated Sonarr/Radarr databases and synthetic files, a controlled downloader/indexer substitute or disposable SAB environment, and tightly scoped test paths. Capture sanitized fixtures with app version, branch, setup configuration, route, wire response and verified resulting state. Test packaged releases as well as normal development environments. Production setup performs nonmutating probes only.

| Contract | Required fixture and lab coverage |
| --- | --- |
| Authentication and detection | URL base, proxy HTML with 200, invalid key, disabled API, redirects, reverse proxy prefix, TLS and stale DNS, healthy empty queue, unsupported version, restart, clone and restored database. |
| Inventory and identity | Queue paging changes between pages, same-count replacements, duplicate Sonarr pack rows, reused row IDs, missing download ID, two Arr instances sharing a SAB category, duplicate downloader display names, conflicting grab history, unknown enum and changed profiles mid-flight. |
| Read-only import probes | Valid singleton, empty tracked output, unknown token, folder inaccessible, remote path mapped, native Windows drive and UNC paths, multiple cuts, sample-only, combined episodes and stale or different release/target. Confirm scoped reprocess changes neither library nor client state. |
| Import effects | Accepted, queued, expired command and lost acknowledgement. Full, partial and zero-file import. Check exact file and history readback and upstream source cleanup. Include upstream copy-to-move/fallback behavior if applicable, folder cleanup while copy is selected, completed-download handling enabled and disabled, shared path, active torrent seeding, and cases where no preservation proof is available. |
| Reject and remove effects | Every flag vector allowed by product design. Missing grab history, native queue row stale, upstream pending item, deletion before failure-event handling, failed blocklist, duplicate prior blocklist, ignored-state semantics, failed client deletion, SAB queue versus history/archive branch, and connection loss at each transition. Confirm exact target isolation and no automatic data deletion for other protocols or shared/partial jobs. |
| Replacement | Confirm `skipRedownload=true` suppresses the failure-triggered search for exact qualified route, while independent Arr activity can still occur. Confirm `EpisodeSearch` and `MoviesSearch` target only intended IDs. Test manual-command monitoring behavior, preexisting replacement, no results, upstream search already running, indexer limit, profile drift, and lost acknowledgement. |
| Capacity and diagnostics | Low destination volume vs healthy downloader storage, low SAB temporary vs complete space, unmapped root, network mount disappearance, duplicated volume aliases, disabled log DB, truncated payload, clock drift and data retention. |
| Prowl | Valid XML acceptance, malformed/oversized XML, per-key errors, hourly quota reset, UTF-8 field length, configured quiet hours, opt-in titles, no key/path in logs, cross-destination isolation, restart with sending event and provider outage with normal recovery progress. |

The pinned source establishes design constraints and adapter candidates. Maintain a published capability matrix tied to the last verified installed builds. Every change to a mutating route, command body, protocol, client version or cleanup predicate must advance its qualification evidence before Autonomous mode can use it. Read-only diagnosis and native-UI handoff keep providing value when an upstream behavior falls outside the tested contract.
